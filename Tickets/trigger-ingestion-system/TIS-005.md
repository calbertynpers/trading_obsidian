## Summary

Upgrade the Lambda event consumer from Phase 1 (notifications only) to Phase 2 (agent evaluation). The Lambda routes events by action_type: simple notifications go direct to Telegram, events needing evaluation invoke Bedrock Claude Sonnet 4 with tool use. The agent evaluates the enriched trigger, decides the response (inform/propose), and communicates via Telegram.

## Architecture

```
SQS "trigger-events" (enriched TriggerEvents)
        │
        ▼
Lambda "event-consumer" (Phase 2):
  1. Deserialise enriched TriggerEvent
  2. Route by action_type / urgency:
     - Simple notification → format → Telegram (no agent)
     - Needs evaluation → invoke Bedrock Agent
  3. Agent evaluates with tools:
     - read_knowledge(path) → EFS /mnt/vault/
     - write_knowledge(path, content) → EFS /mnt/vault/
  4. Agent decides:
     - inform → Telegram notification
     - propose → Telegram proposal + DynamoDB (confirmation flow)
```
