## Summary

Build the price monitor as an independent source process on EC2. Polls BDS for prices, evaluates conditions, normalises fired conditions into TriggerEvents, enriches with BDS position data, and publishes enriched events to SQS via the generic publisher.

This is the first producer — completing the internal trigger path end-to-end (condition fires → SQS → consumer → Telegram).

## Scope

- `trigger_ingestion/run_price_monitor.py` — Entry point (systemd service)
- `tests/test_run_price_monitor.py` — Integration tests

## Key Design Decisions

- Independent process — runs as its own systemd service, no shared event loop with other sources
- Wires together existing TIS-002/003 components (PriceFetcher, ConditionEvaluator, TriggerNormaliser, EnrichmentLayer) + TIS-004 SQSPublisher
- Signal handling (SIGINT/SIGTERM) for graceful shutdown
- Individual trigger failures don't crash the process (log + continue)
- Periodic refresh of watchlist and conditions from SQLite

## Acceptance Criteria

- [ ] Process starts, loads config, opens DB, initialises all components
- [ ] Async loop: poll → evaluate → normalise → enrich → publish (per fired condition)
- [ ] Watchlist and conditions refresh on configured intervals
- [ ] SIGINT/SIGTERM triggers graceful shutdown
- [ ] Individual trigger failure (enrichment or publish) doesn't crash the process
- [ ] End-to-end: condition fires → enriched TriggerEvent appears in SQS queue
