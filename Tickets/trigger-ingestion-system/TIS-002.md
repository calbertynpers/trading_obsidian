## Summary

Build the foundational layer of the TIS: Pydantic schemas (TriggerEvent), YAML configuration loading with env var resolution, SQLite database layer (watchlist + conditions tables), price fetcher via Binance Data Collector `get_snapshot` MCP tool, condition evaluator with cooldown persistence, trigger normaliser, and structured logging.

**Important**: The Price_Fetcher does NOT call the Binance API directly. It queries the Binance Data Collector service via its `get_snapshot` MCP tool. This means the TIS watchlist symbols must be a subset of symbols tracked by the data collector. [[BDS-019]] (`add_to_watchlist` MCP tool) is in place — anything that opens a position (or otherwise registers TIS interest in a symbol) calls `add_to_watchlist` to seed tracking. The end-to-end path is unblocked today.

### Q2 — Optional `*` test tasks in `tasks.md`
**Question:** Every test task in `tasks.md` is marked `*` (optional, "skippable for faster MVP"). This conflicts with CLAUDE.md §6 ("every new function with non-trivial logic gets a test, no exceptions") and the acceptance criteria ("All property tests pass (P1–P5, P15–P17, P19)").
**Decision:** **Property tests are skippable** for this milestone (Hypothesis-based P1–P5, P15–P17, P19 — i.e. tasks 2.5, 3.2, 6.2, 7.2, 9.2, 10.1). Unit tests are still mandatory per CLAUDE.md §6 (tasks 2.6, 3.3, 5.4, 6.3, 7.3, 9.3, 10.2). Acceptance-criterion line "All property tests pass" should be read as conditional on the property tests being written; if we add them later they must pass.

### Q6 — BDS soft-dependency correction (2026-04-26)
**Question:** The original ticket header named [[BDS-015]] (auto pull-based watchlist sync) as the soft dependency, with a note that TIS would be limited to "symbols already in the collector's config" until BDS-015 or BDS-019 shipped. Is that still the right framing now that close-out is in sight?
**Decision:** No — corrected. [[BDS-019]] (`add_to_watchlist` MCP tool) is **already shipped** and is the path TIS will use: callers that introduce a new symbol (position-opener, agent action) push it to the collector via `add_to_watchlist`.
