## Summary

Build the webhook receiver as an independent source process on EC2. Runs FastAPI/Uvicorn, accepts TradingView webhook POSTs, parses payloads, normalises into TriggerEvents, enriches with BDS position data, and publishes enriched events to SQS via the generic publisher.

This is the second producer — completing the external trigger path end-to-end (TV webhook → SQS → consumer → Telegram).

## Scope

- `trigger_ingestion/run_webhook_receiver.py` — Entry point (systemd service)
- `tests/test_run_webhook_receiver.py` — Integration tests

## Key Design Decisions

- Independent process — runs as its own systemd service, separate from price monitor
- Wires together existing TIS-003 components (create_webhook_app, TVPayloadParser, TriggerNormaliser.from_tradingview, EnrichmentLayer) + TIS-004 SQSPublisher
- on_payload callback chain: parse → normalise → enrich → publish
- Uvicorn handles SIGINT/SIGTERM for graceful shutdown
- Individual webhook processing failures return HTTP 500 but don't crash the process

## Acceptance Criteria

- [ ] Process starts Uvicorn on configured host/port
- [ ] Valid TV webhook → parse → normalise → enrich → publish to SQS
- [ ] Invalid webhook → appropriate HTTP error code, process continues
- [ ] SQS publish failure → logged, HTTP 500 returned, process continues
- [ ] End-to-end: TV webhook POST → enriched TriggerEvent appears in SQS queue
