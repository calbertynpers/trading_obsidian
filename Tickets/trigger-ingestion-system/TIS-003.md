## Summary

Add the external trigger path (TradingView webhooks with passphrase authentication), extend the normaliser with `from_tradingview()`, build the BDS enrichment layer (using injected MCP callables), add the AgentPrompt schema, and optionally call `add_to_watchlist` on the Binance Data Collector for new symbols. After this milestone, both trigger sources (internal price conditions and external TV webhooks) produce enriched TriggerEvents with live position data.

## Requirements Covered

- **Req 6**: TradingView Webhook Reception (FastAPI endpoint, passphrase auth)
- **Req 7**: TradingView Payload Parsing (symbol, message extraction)
- **Req 8**: Enrichment with Live Position Data (BDS MCP queries via injected callables, no Binance credentials in TIS)
- **Req 20**: Agent Prompt Schema (Pydantic v2 model — ready for TIS-004)

## Implementation Summary (2026-05-05)

283 tests passing across all suites. Public API exports: `AgentPrompt`, `TVPayloadParser`, `EnrichmentLayer`, `create_webhook_app` added to `trigger_ingestion/__init__.py`. Version bumped to 0.2.0.

**Key implementation details:**
- Webhook passphrase validation uses `hmac.compare_digest` for timing-safe comparison
- Enrichment layer returns `model_copy` (original trigger not mutated)
- `_query_positions` lets exceptions propagate to caller (which decides error context shape)
- Invalid urgency in TV metadata falls back to `"alert"` with DEBUG log
- `POSITION_FIELD_MAP` and `ORDER_FIELDS` class attributes define the BDS → context mapping
