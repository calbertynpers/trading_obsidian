# BDS-016: Fix estimated_8h_funding_cost sign for SHORT positions

**Priority:** Medium
**Status:** 🔴 Open
**Component:** `binance_data_collector` (Position Tools — funding snapshot)
**Type:** Bug
**Reported:** 2026-04-23

---

## Summary

`estimated_8h_funding_cost` is computed as a literal `position_size × mark_price × funding_rate`, ignoring position side. For SHORT positions this misrepresents the holder's P&L: on a positive funding rate a SHORT *receives* funding, but the current output shows a positive cost as if they were paying.

## Problem

Observed on `NAORISUSDT` SHORT with funding rate `+0.00005`:

- Output: `estimated_8h_funding_cost = +0.025`
- Actual holder experience: SHORT *receives* ~0.025 (positive funding → longs pay shorts)

The formula in code matches "notional × rate" as written, but the field name `estimated_8h_funding_cost` implies a holder-perspective value (negative = you pay, positive = you receive, or the inverse). Without a sign flip for SHORT, the number is misleading whenever a user reads it as "what this position costs me in funding."

## Root Cause

Decide which of these was intended:

1. **Literal notional × rate** — current behavior. Name is misleading; the value is a raw market quantity, not a P&L figure for the holder.
2. **Holder-perspective cost** — SHORT sign should flip so positive means "you pay" and negative means "you receive" (or vice versa; pick one and document).

The spec (`.kiro/specs/bds-014-funding-oi-snapshot/`) needs to be re-read to confirm intent before patching.

## Proposed Approach

Assuming holder-perspective is intended (most useful reading):

1. Multiply by `-1` when `position_side == "SHORT"` (or equivalently, use signed `position_amt`).
2. Document the sign convention in the tool description: e.g. "positive = funding you pay, negative = funding you receive."
3. Add unit tests covering LONG/SHORT × positive/negative funding rate (four cases).

If literal notional × rate was intended, rename the field to `estimated_8h_funding_notional` (or similar) to remove the "cost" connotation, and document.

## Acceptance Criteria

- [ ] Spec intent confirmed (holder-perspective vs. literal notional) and recorded in `design.md`.
- [ ] Output value matches intent for all four LONG/SHORT × positive/negative-rate combinations.
- [ ] Field name matches meaning (either keep `estimated_8h_funding_cost` with sign flip, or rename).
- [ ] Tool description documents the sign convention.
- [ ] Unit tests cover the four sign combinations.
