## Summary

Add a `get_income_history` tool that queries the Binance Futures income endpoint (`GET /fapi/v1/income`) to retrieve realized PnL, commissions, funding payments, and other income records across ALL symbols. Unlike order history (BDS-008), this endpoint does not require a symbol parameter, making it the only way to discover round-trip trades on symbols that are no longer held.

## Problem

The `get_order_history` tool (BDS-008) requires a symbol parameter because the Binance API mandates it. This means we can't discover positions that were fully opened and closed within a time window unless we already know which symbols to query. The income endpoint solves this by returning realized PnL records across all symbols.

## Binance API

- Endpoint: `GET /fapi/v1/income`
- Symbol is **optional** — can query across all symbols
- Supports `incomeType` filter: REALIZED_PNL, COMMISSION, FUNDING_FEE, TRANSFER, etc.
- Supports `startTime` / `endTime` for time filtering
- Returns: symbol, incomeType, income (amount), asset, time, info, tranId, tradeId

## Use Cases

1. **Daily P&L summary** — Query REALIZED_PNL for the day to see all closed trades and their P&L
2. **Funding cost tracking** — Query FUNDING_FEE to see total funding paid/received across all positions
3. **Commission tracking** — Query COMMISSION to see total trading fees
4. **Round-trip trade discovery** — Find symbols with realized PnL that are no longer in the active positions list (fully closed trades)
5. **Trade journaling** — Combined with `get_order_history`, provides complete trade lifecycle data
