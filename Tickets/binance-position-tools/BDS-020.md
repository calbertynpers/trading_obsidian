## Summary

Add a database adapter abstraction to the Binance Data Collector that supports both SQLite (local dev) and PostgreSQL (AWS production). The collector and MCP servers currently use `aiosqlite` directly. This ticket introduces an adapter pattern so the same codebase runs against either backend, selected by configuration.

## Context

The AWS Deployment Framework ([[ADF-005]]) will deploy BDS to an EC2 instance backed by RDS PostgreSQL. The code currently hardcodes `aiosqlite`. This ticket makes the code database-agnostic so it works in both environments:

- **Local development:** SQLite (existing behavior, zero setup)
- **AWS production:** PostgreSQL via RDS (concurrent access, durability, shared across services)

## Configuration

Backend selected via environment variable or config:

```yaml
# collector_config.yml
database:
  backend: sqlite          # sqlite | postgresql
  # SQLite settings (used when backend=sqlite)
  sqlite_path: "data/market_data.db"
  # PostgreSQL settings (used when backend=postgresql)
  postgresql_url: "${DATABASE_URL}"  # or individual host/port/db/user/pass
```

Or via environment variable:
```
DATABASE_BACKEND=postgresql
DATABASE_URL=postgresql://bds_app:xxx@trading-db-prod.xxxxx.eu-north-1.rds.amazonaws.com:5432/bds_prod
```

## PostgreSQL Schema

Same as SQLite but with PostgreSQL types (defined in [[ADF-004]]):

```sql
CREATE TABLE latest_snapshots (
    symbol VARCHAR(20) PRIMARY KEY,
    last_price DOUBLE PRECISION,
    price_change_pct_24h DOUBLE PRECISION,
    high_24h DOUBLE PRECISION,
    low_24h DOUBLE PRECISION,
    quote_volume_24h DOUBLE PRECISION,
    num_trades_24h INTEGER,
    mark_price DOUBLE PRECISION,
    funding_rate DOUBLE PRECISION,
    next_funding_time BIGINT,
    collected_at TIMESTAMPTZ NOT NULL
);

CREATE TABLE snapshot_history (
    id BIGSERIAL PRIMARY KEY,
    symbol VARCHAR(20) NOT NULL,
    last_price DOUBLE PRECISION,
    price_change_pct_24h DOUBLE PRECISION,
    high_24h DOUBLE PRECISION,
    low_24h DOUBLE PRECISION,
    quote_volume_24h DOUBLE PRECISION,
    num_trades_24h INTEGER,
    mark_price DOUBLE PRECISION,
    funding_rate DOUBLE PRECISION,
    next_funding_time BIGINT,
    collected_at TIMESTAMPTZ NOT NULL
);

CREATE INDEX idx_history_symbol_time ON snapshot_history (symbol, collected_at);

CREATE TABLE dynamic_watchlist (
    symbol VARCHAR(20) PRIMARY KEY,
    added_at TIMESTAMPTZ NOT NULL,
    added_by VARCHAR(50) NOT NULL
);
```

## Notes

- Keep the adapter interface minimal — only the methods currently used by collector + MCP servers
- asyncpg is much faster than psycopg2 for async workloads — good fit
- Connection pooling is important for PostgreSQL (asyncpg has built-in pool)
- Consider using `UPSERT` (INSERT ON CONFLICT) for `latest_snapshots` — works in both SQLite and PostgreSQL
- The position tools MCP server doesn't use the database (it calls Binance API directly) — no changes needed there
