# BDS-015: Dynamic Watchlist Sync from Active Positions

**Priority:** Medium
**Status:** 🔴 Open
**Component:** `binance_data_collector` (Collector Service)
**Type:** Feature
**Reported:** 2026-04-22

---

## Summary

Automatically sync the data collector's watchlist with the trader's active Binance Futures positions, so that historical price, volume, and funding rate data is always captured for every held coin — not just the manually configured watchlist.

## Problem

The data collector polls Binance every 60s and stores snapshots in SQLite, but only for symbols in `config/collector_config.yml` watchlist. If a trader opens a position on a new coin (e.g., NAORIS, CHIP), historical data collection doesn't start until someone manually adds it to the config. This means:

- `get_history` returns no data for recently added positions
- `get_metrics` (price velocity, volume spike, funding trend) can't compute for new coins
- Historical funding rate time series is missing for coins not on the watchlist
- The trader loses the ability to analyze trends on coins they're actively trading

## Proposed Approach

1. **Periodic position sync**: Every N poll cycles (configurable, e.g., every 5 minutes), query active positions via the Binance API and merge discovered symbols into the in-memory watchlist
2. **Additive only**: New symbols are added but never removed automatically (a position might be closed but historical data is still valuable)
3. **Config file unchanged**: The YAML watchlist remains the "seed" list. Dynamic additions are in-memory only and logged
4. **Optional**: Controlled by a config flag `auto_sync_positions: bool = false` so existing behavior is preserved

## Binance API

- `GET /fapi/v2/positionRisk` — returns all positions (requires auth). Already used by position-tools.
- Alternative: `GET /fapi/v2/account` — returns positions as part of account info

## Acceptance Criteria

- [ ] New config option `auto_sync_positions` (default false) in collector_config.yml
- [ ] When enabled, collector queries active positions every N cycles and adds new symbols to the in-memory watchlist
- [ ] Newly discovered symbols start appearing in `snapshot_history` within one poll cycle of detection
- [ ] YAML config file is not modified (dynamic additions are in-memory only)
- [ ] Symbols from the YAML watchlist are always included regardless of position status
- [ ] Log INFO when new symbols are discovered and added
- [ ] Requires API credentials (same as position-tools) — config must include `api_key` and `api_secret` or env vars

## Considerations

- The collector currently uses public endpoints only (no auth). This feature would require adding authenticated API access to the collector service, or querying the position-tools MCP server.
- Alternative: have the position-tools server expose a "get active symbols" tool that the collector can call, keeping auth in one place.
- Another alternative: a manual "add to watchlist" MCP tool that the agent can call when it opens a new position.
