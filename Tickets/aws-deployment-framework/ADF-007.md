## Summary

Host a basic web UI for monitoring trading positions, P&L, funding costs, and open orders. The frontend is a static React/Vite app served from S3 + CloudFront. It calls a lightweight API on the EC2 that queries RDS for live data.

## Architecture

```
┌─────────────┐     HTTPS      ┌──────────────┐
│  Browser     │ ──────────────▶│  CloudFront   │
│  (you)       │                │  (CDN + HTTPS)│
└─────────────┘                └──────┬───────┘
                                      │
                          ┌───────────▼───────────┐
                          │  S3 Bucket             │

┌─────────────┐     HTTPS      ┌──────────────────┐

└─────────────┘                └────────┬──────────┘

                               └────────────────────┘
```

## Frontend Stack

- **React + Vite** — fast build, minimal config
- **TanStack Query** — data fetching and caching
- **Tailwind CSS** — utility-first styling, fast to build with
- **Recharts or lightweight charting lib** — P&L curves, funding charts

## Backend API (on EC2)

A thin API layer that queries RDS and returns JSON. Options:

| Option | Language | Notes |
|--------|----------|-------|
| **FastAPI** | Python | Matches BDS stack, can reuse asyncpg connection, quick to build |
| **Express** | Node.js | If frontend devs prefer JS end-to-end |

FastAPI is the natural choice — same Python ecosystem as BDS, shares the RDS connection pool, and you can expose position data endpoints without duplicating the Binance API integration.

## Dashboard Views (MVP)

1. **Positions overview** — all open positions with entry price, current price, unrealized P&L, leverage, liquidation distance
2. **P&L summary** — daily/weekly realized P&L, funding costs, commissions
3. **Open orders** — pending limit, stop, TP orders grouped by symbol
4. **Funding monitor** — current funding rates across positions, estimated 8h cost

## Authentication

Personal use only — keep it simple:
- **Option A:** API key in request header, validated by FastAPI middleware
- **Option B:** CloudFront signed URLs or Lambda@Edge for basic auth
- **Option C:** IP whitelist on the API (your home IP only)

Recommend Option A + C combined — API key for the API, IP whitelist as defense in depth.
