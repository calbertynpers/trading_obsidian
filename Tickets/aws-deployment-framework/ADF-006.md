# ADF-006: CI/CD Pipeline for Service Deployments

**Priority:** Medium
**Status:** 🔴 Open
**Component:** `aws-deployment-framework`
**Type:** Infrastructure
**Reported:** 2026-05-03
**Depends On:** [[ADF-005]]

---

## Summary

Create a reusable CI/CD pipeline using CodeBuild and CodeDeploy that automates deployments to the EC2 instance. Triggered by pushes to main branch on GitHub. First target: BDS, then reusable for TIS, TMS, and other services.

## Architecture

```
GitHub (push to main)
       │
       ▼
CodePipeline (trading-pipeline-bds)
       │
       ├─ Source Stage: GitHub webhook
       │
       ├─ Build Stage: CodeBuild
       │   ├─ Run tests
       │   ├─ Build artifacts
       │   └─ Package for deployment
       │
       └─ Deploy Stage: CodeDeploy
           ├─ Stop systemd services
           ├─ Pull latest code
           ├─ Install dependencies (uv)
           ├─ Run migrations (if any)
           └─ Restart systemd services
```

## Tasks

- [ ] Create CodeBuild project for BDS (buildspec.yml in BDS repo)
- [ ] Create CodeDeploy application and deployment group targeting EC2
- [ ] Install CodeDeploy agent on EC2 instance
- [ ] Create appspec.yml for BDS deployment lifecycle hooks
- [ ] Create CodePipeline connecting Source → Build → Deploy
- [ ] Create CloudFormation template `templates/pipeline.yml` (parameterized per service)
- [ ] Test end-to-end: push to BDS main → auto-deploy to EC2
- [ ] Add manual approval gate option for production deployments
- [ ] Document how to add a new service to the pipeline

## CodeDeploy Lifecycle (appspec.yml)

```yaml
version: 0.0
os: linux
files:
  - source: /
    destination: /opt/trading/bds/binance_data_collector
hooks:
  BeforeInstall:
    - location: scripts/codedeploy/before-install.sh
      timeout: 60
  AfterInstall:
    - location: scripts/codedeploy/after-install.sh
      timeout: 120
  ApplicationStart:
    - location: scripts/codedeploy/application-start.sh
      timeout: 60
  ValidateService:
    - location: scripts/codedeploy/validate-service.sh
      timeout: 60
```

## Acceptance Criteria

- [ ] Push to BDS main triggers automated deployment
- [ ] Tests run in CodeBuild before deployment proceeds
- [ ] Failed tests block deployment
- [ ] CodeDeploy stops services, updates code, restarts services
- [ ] Rollback works if deployment fails
- [ ] Pipeline is parameterized — can be reused for other services

## Notes

- CodeDeploy agent needs to be installed on EC2 (add to ec2-setup.sh)
- GitHub connection via CodeStar Connections or OAuth token
- Start simple — no approval gates initially, add later for production confidence
- The pipeline template should be parameterized so adding a new service is just a new stack with different params
