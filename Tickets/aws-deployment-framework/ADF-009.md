# ADF-009: Lambda Functions + DynamoDB + API Gateway for TIS Agent Layer

**Priority:** High
**Status:** 🔴 Open
**Component:** `aws-deployment-framework`
**Type:** Infrastructure
**Reported:** 2026-05-05
**Depends On:** [[ADF-008]], [[ADF-002]]

---

## Summary

Provision the serverless infrastructure for the TIS agent dispatch and confirmation layer: Lambda functions, DynamoDB table for pending confirmations, and optionally API Gateway for Telegram webhook delivery.

## Resources

### Lambda Functions

| Function | Trigger | Timeout | Memory | Concurrency |
|----------|---------|---------|--------|-------------|
| `trading-prod-agent-dispatcher` | SQS trigger-events | 180s | 512MB | Reserved = 1 |
| `trading-prod-confirmation-handler` | EventBridge (3s schedule) or API Gateway | 30s | 256MB | Unreserved |
| `trading-prod-agent-executor` | SQS execution | 180s | 512MB | Reserved = 1 |

**Runtime:** Python 3.12 (or container image with Python 3.14 if needed for pydantic v2 features)

**Layers:** Common layer with `pydantic`, `httpx`, `boto3` (or bundled in deployment package)

### DynamoDB Table

| Property | Value |
|----------|-------|
| Table Name | `trading-prod-pending-confirmations` |
| Partition Key | `trigger_id` (String) |
| GSI | `message_id-index` on `message_id` (Number) |
| TTL Attribute | `ttl` (Number, epoch seconds) |
| Billing | On-demand (pay per request) |

**Schema:**
```
{
  trigger_id: String (PK),
  message_id: Number (GSI),
  execution_plan: String (JSON),
  symbol: String,
  status: String ("pending" | "confirmed" | "rejected"),
  created_at: Number (epoch),
  ttl: Number (epoch + timeout)
}
```

### API Gateway (Optional — Phase 2)

| Property | Value |
|----------|-------|
| Type | HTTP API (cheaper than REST API) |
| Route | POST /telegram-webhook |
| Integration | Lambda `confirmation-handler` |
| Auth | None (Telegram validates via secret token in URL path) |

**Phase 1:** Use EventBridge scheduled rule (every 3s) to poll TMS-002 for replies.
**Phase 2:** Switch to API Gateway webhook for real-time delivery.

### DynamoDB Streams (for timeout notifications)

Enable DynamoDB Streams on the table. When TTL deletes an item, the stream event triggers a Lambda that sends a timeout notification to Telegram.

| Function | Trigger | Purpose |
|----------|---------|---------|
| `trading-prod-timeout-notifier` | DynamoDB Streams (REMOVE events) | Send timeout notification to Telegram |

## IAM Roles

| Role | Permissions |
|------|-------------|
| `trading-prod-agent-dispatcher-role` | SQS (receive/delete trigger-events), DynamoDB (put pending-confirmations), Bedrock (invoke agent), SSM (read params), Secrets Manager (read) |
| `trading-prod-confirmation-handler-role` | DynamoDB (query/update pending-confirmations), SQS (send to execution queue), SSM (read params) |
| `trading-prod-agent-executor-role` | SQS (receive/delete execution), Bedrock (invoke agent), SSM (read params), Secrets Manager (read) |
| `trading-prod-timeout-notifier-role` | DynamoDB Streams (read), HTTP outbound (Telegram API) |
