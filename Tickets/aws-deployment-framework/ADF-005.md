## Summary

Deploy the Binance Data Collector service to the EC2 instance. The code changes (asyncpg migration) are handled in [[BDS-020]] in the BDS repo. This ticket covers the deployment infrastructure: systemd services, startup scripts, and the deploy script.

## Sequence

```
BDS-020 (BDS repo)          ADF-003 + ADF-004 (this repo)
  │ asyncpg adapter            │ Secrets Manager + RDS
  │ code changes               │ infrastructure
  └──────────┬─────────────────┘
             │
             ▼
        ADF-005 (this repo)
          Deploy to EC2
```

**BDS-020 and ADF-003/ADF-004 can run in parallel.** ADF-005 needs all three done before the actual deployment and verification.

The deploy scripts and systemd units in this ticket can be written in parallel with BDS-020 — they don't depend on the code changes.

## Architecture on EC2

```
/opt/trading/bds/
├── venv/                          # Python venv (uv, Python 3.14)
├── binance_data_collector/        # Application code (git clone)
├── config/
│   └── collector_config.yml       # Watchlist, poll interval, DB=postgresql
├── logs/
│   ├── collector.log
│   ├── data-mcp.log
│   └── position-mcp.log
└── scripts/
    ├── start-collector.sh         # Pulls secrets, starts collector
    ├── start-data-mcp.sh          # Starts data MCP server
    └── start-position-mcp.sh      # Pulls secrets, starts position MCP
```

## Tasks (this repo — deployment infra)

- [ ] Create `scripts/deploy-bds.sh` — clones/pulls BDS repo, creates venv, installs deps
- [ ] Create `scripts/bds/start-collector.sh` — pulls secrets from Secrets Manager, exports env vars, starts collector
- [ ] Create `scripts/bds/start-data-mcp.sh` — starts data MCP server
- [ ] Create `scripts/bds/start-position-mcp.sh` — pulls secrets, starts position MCP
- [ ] Create systemd unit files in `templates/systemd/`:
  - `bds-collector.service`
  - `bds-data-mcp.service`
  - `bds-position-mcp.service`
- [ ] Create `scripts/install-bds-services.sh` — copies units to `/etc/systemd/system/`, enables and starts
- [ ] Create `collector_config.yml` template with PostgreSQL backend configured
- [ ] Deploy to EC2 and verify all services start
- [ ] Test service recovery (kill process → systemd restarts)
- [ ] Verify collector writes to RDS
- [ ] Verify MCP servers read from RDS

## Environment Variables (set by startup scripts via Secrets Manager)

```bash
DATABASE_BACKEND=postgresql
DATABASE_URL=postgresql://bds_app:<password>@<rds-endpoint>:5432/bds_prod
BINANCE_API_KEY=<from secrets manager>
BINANCE_SECRET_KEY=<from secrets manager>
```

## Acceptance Criteria

- [ ] All three systemd services running and enabled (survive reboot)
- [ ] Collector writes to RDS `bds_prod.latest_snapshots` every 60s
- [ ] `snapshot_history` table growing
- [ ] Data MCP server returns valid data from RDS
- [ ] Position MCP server authenticates to Binance
- [ ] Services auto-restart on crash
- [ ] Logs rotate correctly

## Notes

- The deploy script should be idempotent (safe to re-run)
- MCP servers on EC2 won't be directly accessible from local Kiro yet — future ticket
- Primary value: collector running 24/7 without Mac needing to be on
- Position tools MCP server doesn't use the database — it only needs Binance API credentials
