## Approach (agreed 2026-05-04)

**AWS account:** `950858585111` (IAM user `clint`), region `eu-north-1`. No account alias / no AWS Organizations.

### Design choices

1. **Secret values stay out of CloudFormation/git.**
   The template declares the secret *containers* with a placeholder `SecretString`. Real Binance values are populated post-deploy via `aws secretsmanager put-secret-value`. Stack updates never risk overwriting credentials, and rotation never touches CloudFormation.

2. **`pull-secrets.sh` is sourced, not executed.**
   Systemd units / service wrappers `source` it so env vars land in the service's environment without ever hitting disk. Script fails loudly on missing secret or IAM denial.

## Update 2026-05-04: Secret paths now env-scoped

Decision: secret paths include the environment from day one, to avoid a painful rename when dev/staging stacks arrive.

**Old path → new path**
- `/trading/binance/ec2-api-key` → `/trading/${Environment}/binance/ec2-api-key`
- `/trading/binance/ec2-api-secret` → `/trading/${Environment}/binance/ec2-api-secret`

For the current prod deploy these resolve to:
- `/trading/prod/binance/ec2-api-key`
- `/trading/prod/binance/ec2-api-secret`

**Files updated:**
- `templates/secrets.yml` — secret `Name` and the populate-command outputs use `!Sub` with `${Environment}`.
- `scripts/pull-secrets.sh` — reads `TRADING_ENV` (defaults to `prod`) and constructs paths from it.

**No IAM changes needed.** The existing role policy on `arn:...:secret:/trading/*` already covers env-scoped paths via the wildcard.

The initial deploy had used non-scoped paths and was redeployed under the new scheme. CloudFormation hard-deleted the old secrets on replacement (no recovery window), so the populated values had to be re-pasted into the new paths.

### Lessons captured

1. **CloudFormation `AWS::SecretsManager::Secret` replacement hard-deletes the old secret** (no recovery window) when a `Name` change forces replacement. If migrating paths in the future, capture values first via `get-secret-value`.
2. **Sourced bash scripts cannot use `return` from inside a function to exit the script** — `return` only exits the function itself. Use a top-level `${__HALT}` variable holding `exit` or `return` and invoke inline at each failure point.
