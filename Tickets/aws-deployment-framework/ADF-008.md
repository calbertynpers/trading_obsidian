# ADF-008: SQS Queues for Trigger Ingestion System

## Summary

Provision SQS queues for the Trigger Ingestion System's event-driven architecture. Two queues: one for enriched trigger events (consumed by the agent dispatch Lambda) and one for confirmed execution plans (consumed by the agent executor Lambda). Each queue has a dead-letter queue for failed messages.

## Resources

### 1. Trigger Events Queue

| Property | Value |
|----------|-------|
| Name | `trading-prod-trigger-events` |
| Type | Standard (not FIFO — ordering not critical) |
| Visibility Timeout | 180s (agent_response_timeout + buffer) |
| Message Retention | 4 hours (stale triggers shouldn't be evaluated) |
| Receive Wait Time | 20s (long polling) |
| DLQ | `trading-prod-trigger-events-dlq` |
| Max Receive Count | 3 (before DLQ) |

### 2. Execution Queue

| Property | Value |
|----------|-------|
| Name | `trading-prod-execution` |
| Type | Standard |
| Visibility Timeout | 180s |
| Message Retention | 1 hour (confirmed plans should execute quickly) |
| Receive Wait Time | 20s |
| DLQ | `trading-prod-execution-dlq` |
| Max Receive Count | 2 (execution failures shouldn't retry many times) |

### 3. Dead-Letter Queues

| Name | Retention |
|------|-----------|
| `trading-prod-trigger-events-dlq` | 14 days |
| `trading-prod-execution-dlq` | 14 days |

## IAM

- EC2 instance role needs `sqs:SendMessage` on trigger-events queue
- Agent dispatch Lambda role needs `sqs:ReceiveMessage`, `sqs:DeleteMessage` on trigger-events queue
- Agent dispatch Lambda role needs `sqs:SendMessage` on execution queue (for confirmed plans from confirmation handler)
- Confirmation handler Lambda role needs `sqs:SendMessage` on execution queue
- Agent executor Lambda role needs `sqs:ReceiveMessage`, `sqs:DeleteMessage` on execution queue
