## Summary

Concrete `MCPDataProvider` implementation that owns the mapping from real MCP response shapes onto the analyser's internal contract. Removes the per-caller hand-rolled adapter duplication that surfaced in the IDS-002 BTC dry-run (`scripts/dry_run_btc.py`). Lives at `pine_generator/providers/live_mcp.py`.

---

## Context

IDS-002 ships an `MCPDataProvider` Protocol that `analyse_symbol(request, provider)` consumes. The Protocol defines four async methods (`tv_daily_analysis`, `tv_4h_analysis`, `bds_snapshot`, `bds_position`) returning dicts with documented keys.

The 2026-04-28 BTC dry-run confirmed that **real MCP responses don't match those keys**:
- TV `coin_analysis` returns `support_resistance.{resistance_1, resistance_2, resistance_3, support_1, support_2, support_3}` — numbered keys, not `resistance_levels: list[float]` arrays.
- TV `coin_analysis` 4h returns `bollinger_bands.{upper, middle, lower}`, not `bollinger_upper / bollinger_middle / bollinger_lower` at top level.
- TV pivot-derived `resistance_1` can sit *below* current price, mis-classifying it if used naively.
- BDS `get_snapshot` returns `{"error": "Database file not found..."}` when the service is down — needs to be recognised as a source failure rather than mis-parsed.
- BDS `get_positions` returns the entire portfolio — needs filtering by the requested symbol.

Today every caller (the dry-run script, future agent invocations, the IDS-003 notebook generator) re-implements this mapping. This ticket promotes it into a single tested module.

---

## Design Choice — Agent-Side Adapter (not Python MCP Client)

Two options were considered:

1. **Agent-side adapter** ✅ — provider takes raw MCP responses upfront (agent fetches them), exposes the Protocol async methods that return mapped views. Simple, no MCP client library, fits the agent-driven POC workflow.
2. **Python MCP client** — provider opens stdio/SSE connections and calls MCP tools directly. More moving parts (config, auth, lifecycle); belongs to TIS-007 production wiring.

This ticket implements **option 1**. The agent (or `scripts/generate_notebook.py` for IDS-003) is responsible for calling MCP tools; the provider is responsible for shape-translation only.

## Acceptance Criteria

### Provider implementation
- [ ] `pine_generator/providers/live_mcp.py` defines `LiveMCPDataProvider` implementing the existing `MCPDataProvider` Protocol — `analyse_symbol(request, provider)` works against it with zero changes.
- [ ] Provider is constructed from raw MCP responses (e.g. `LiveMCPDataProvider(tv_daily=..., tv_4h=..., bds_snapshot=..., bds_positions=...)` or a `from_responses(...)` classmethod). Caller has already invoked the MCP tools and passes the dicts in.

### Response mapping
- [ ] **TV daily**: maps `price_data.{high, low}` and `support_resistance.{resistance_1..3, support_1..3}` into the analyser's expected `{high, low, resistance_levels, support_levels}` shape.
- [ ] **TV 4h**: maps `price_data.{high, low}` and `bollinger_bands.{upper, middle, lower}` into `{high, low, bollinger_upper, bollinger_middle, bollinger_lower}`.
- [ ] **Pivot re-tagging**: any pivot-derived level whose price is below current price is returned in `support_levels`; any level above current price is returned in `resistance_levels`. Source naming from TV is discarded — only price position decides.
- [ ] **BDS snapshot**: extracts `last_price`. If the response has shape `{"error": ...}` (or any non-snapshot shape), the provider raises so the analyser's source-degradation path kicks in (matches the dry-run behaviour).
- [ ] **BDS positions**: filters `current_positions` by the requested symbol; returns the matched dict (mapped to the position-payload contract) or `None` if no position for that symbol. Does not raise on "no position" — that's the normal case.

### Tests
- [ ] Unit tests under `tests/pine_generator/providers/test_live_mcp.py` using fixtures derived from real captured MCP responses (start with the BTCUSDT capture in `scripts/dry_run_btc.py`).
- [ ] Cover: happy path for each setup type, BDS-down error shape, pivot re-tagging when `resistance_1` < current price, no-position case for `bds_position`, missing keys gracefully degraded.
- [ ] All 90+ existing IDS-002 tests still pass; integration test in `test_integration.py` updated to drive the pipeline through `LiveMCPDataProvider` for at least one setup type.

### Refactor
- [ ] `scripts/dry_run_btc.py` ad-hoc adapter is replaced with `LiveMCPDataProvider` to prove the abstraction matches the real use case.
