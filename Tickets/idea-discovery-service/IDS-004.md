## Summary

Generate a reactive Marimo notebook for a given symbol so the user can review the proposed trade setup visually on desktop, adjust parameters interactively, and produce the final Pine Script — all before anything touches TradingView.

The notebook can be triggered manually (`scripts/generate_notebook.py BTCUSDT ftp`) or by an upstream scanner (see [[IDS-003]]). This ticket covers the notebook template, generator script, and setup log. The RSI scanner that automates triggering is a separate concern in [[IDS-003]].

---

## Context

After the IDS-002 POC validated that agent-generated Pine Scripts produce profitable setups (BTC trade confirmed 2026-05-01), the next step is a visual review layer. The user needs to:

1. See the proposed levels on a real candlestick chart
2. Adjust parameters (entry zone, TPs, stop) interactively
3. Generate the final Pine Script with adjusted values
4. Copy/save and paste into TradingView

A Marimo notebook is the right medium — desktop-bound, reactive, and produces a durable record of each setup reviewed. Telegram's role is limited to notification ("notebook ready, open it here") handled by [[IDS-003]].

---

## Requirements

### Notebook contents

**Section 1 — Market snapshot**
- Symbol, timeframe (default 1h), current price, 24h change
- RSI value and BB position (if provided by caller)
- Setup type recommended (FTP / SR_Map / Mean Reversion) with one-line rationale

**Section 2 — Chart**
- Candlestick chart, last 100 candles on selected timeframe
- Data source: Binance Futures public klines endpoint (`GET /fapi/v1/klines`) — no auth required
- Overlays: Bollinger Bands (20, 2σ), EMA 50
- RSI panel below the main chart (14-period)
- Horizontal lines for all S/R levels fetched from TradingView `coin_analysis`
- Entry zone shaded (semi-transparent rectangle)
- TP levels as dashed green lines, stop as dashed red line

**Section 3 — Setup parameters (editable)**
Marimo UI elements (sliders / number inputs) for:
- Setup type selector (FTP / SR_Map / Mean Reversion)
- Entry zone bounds (high / low)
- TP 1, TP 2 (optional TP 3)
- Stop level
- Timeframe selector (1h / 4h / 1D)

Changing any parameter reactively re-renders the chart annotations and the Pine Script preview below.

**Section 4 — Pine Script output**
- Calls into IDS-002 `pine_generator` with the current parameter values
- Displays the generated Pine Script in a read-only code block
- "Copy to clipboard" button
- "Save to file" button — writes `setups/SYMBOLUSDT-YYYY-MM-DD-HHMM.pine` alongside the notebook

**Section 5 — Setup log**
- Timestamp, symbol, setup type, key levels, decision (Reviewed / Skipped)
- Written to `setups/log.json` on save

## Generator script

`scripts/generate_notebook.py` is the CLI entry point:

1. Takes `symbol`, `setup_type` as required args; optional `--timeframe`, `--rsi`, `--direction`
2. Pulls S/R levels via TradingView `coin_analysis` MCP (agent calls the tool, passes raw response)
3. Hands the responses to `LiveMCPDataProvider` ([[IDS-005]]) and runs the IDS-002 analyser to get initial parameter values
4. Renders the Marimo notebook from a template, substituting the values
5. Saves to `setups/SYMBOLUSDT-YYYY-MM-DD-HHMM.py`
6. Prints the path to stdout (callers like IDS-003 can use this for Telegram notification)

---

## Notebook file format

Marimo notebooks are plain `.py` files — version-controllable, diffable, openable with `marimo edit <file>`. Each generated notebook is self-contained: it imports from `pine_generator` (IDS-002 + IDS-005) and fetches live kline data on open (cached for the session to avoid rate limits during parameter tweaking).

## Integration points

| System | How |
|---|---|
| IDS-002 Pine generator | Imported directly — `from pine_generator import generate_script` |
| IDS-005 `LiveMCPDataProvider` | Imported — wraps raw MCP responses for the analyser |
| TradingView MCP | `coin_analysis` called by agent/script to seed S/R levels |
| Binance public API | Klines fetched inside the notebook for the chart (cached on open) |
| IDS-003 RSI scanner | Upstream — calls `generate_notebook.py` when RSI extreme found |
| Telegram MCP | Notification sent by IDS-003, not by this ticket |
| TIS-007 | Downstream — Pine Script pasted manually into TradingView after notebook review |

## Resolved questions

- **Marimo version:** 0.10.x — needs to be added to `idea_discovery_service` venv dependencies
- **Kline caching:** Cache on open — avoids rate limits during parameter tweaking. Fresh data on each notebook open.
- **Multiple TPs:** Yes, IDS-002 supports multiple TPs (tp_1, tp_2, etc.). The notebook exposes TP 1 and TP 2 as editable fields, with optional TP 3.
