# IDS-001: TradingView Community Ideas — Access Research Spike

**Priority:** Medium
**Status:** 🔴 Open
**Component:** New Service — `idea_discovery_service`
**Type:** Research Spike
**Reported:** 2026-04-26
**Depends On:** [[TIS-004]]

---

## Summary

Research and design a mechanism to ingest TradingView community trading ideas (setups, theses, hypotheses posted by traders) into the agentic pipeline as a third external trigger source alongside internal price conditions and TradingView webhook alerts.

The goal is to surface relevant, high-quality trading ideas from the TV community for specific symbols and route them through the TIS enrichment and agent evaluation flow, enabling the agent to assess community setups against live position context.

---

## Problem

The TIS currently accepts two signal sources:
- **Internal** — price threshold conditions stored in SQLite
- **External** — TradingView webhook alerts configured manually in the TV UI

Neither source captures the analytical work posted by the TradingView community — trade setups, resistance/support theses, entry/exit hypotheses, multi-timeframe analyses — which represent a valuable but currently inaccessible signal layer.

---

## Access Options

### Option 1: TradingView RSS Feeds ✅ Recommended Starting Point

TradingView publishes public RSS feeds for community ideas by symbol:

```
https://www.tradingview.com/ideas/{SYMBOL}/rss/
```

- No authentication required
- Returns structured XML: title, author, description (truncated), publish date, idea URL
- Publicly accessible — not scraping in the traditional sense
- **Limitation:** idea body is truncated in the feed; full analysis text requires loading the idea page

**Integration path:** RSS poller service polls feeds for watchlist symbols at a configurable interval, parses new ideas, filters by recency and optionally by author reputation/likes, and routes them as `TriggerEvent` with `source: "tradingview_idea"` into the TIS.

### Option 2: Browser-Assisted Full-Text Reading (Claude in Chrome)

When an RSS item is detected, use Claude in Chrome to open the full idea page and extract the complete analysis text, chart annotations, and target levels. Avoids raw scraping while accessing full content.

- More robust than HTTP scraping
- Adds latency (browser open + page load + extraction)
- Dependent on Claude in Chrome availability
- Suitable for high-signal ideas flagged by RSS poller

### Option 3: Unofficial TradingView Internal API ⚠️ Not Recommended

TradingView's frontend communicates with an undocumented internal API that some third parties have reverse-engineered. Provides richer data than RSS.

- Unofficial, unversioned — can break at any time
- No support or stability guarantees
- ToS risk

### Option 4: Raw Web Scraping ❌ ToS Risk

Automated HTTP scraping of TV idea pages is prohibited by TradingView's Terms of Service. Fragile, detectable, and carries legal/access risk.

## Open Questions

1. **ToS position on RSS polling** — is automated RSS consumption explicitly permitted? (RSS is a standard syndication mechanism but high-frequency polling could be restricted)
2. **Full-text access** — what is the minimum viable content from the truncated RSS description vs the value of the full idea body? Can the truncated description alone provide enough signal for agent evaluation?
3. **Quality filtering** — how do we filter for high-quality ideas? Options: minimum likes threshold, followed authors only, verified authors only, ideas with price targets specified
4. **Author reputation model** — should the system weight ideas by author track record? Requires storing historical idea outcomes.
5. **Idea deduplication** — same setup posted by multiple authors; how do we detect and deduplicate?
6. **Symbol coverage** — poll only watchlist symbols, or broader universe?
7. **Update frequency** — how often to poll RSS per symbol without risk of rate limiting?

## TriggerEvent Integration Design

If implemented, TV community ideas would normalise into the standard TriggerEvent schema:

```python
TriggerEvent(
    source="tradingview_idea",           # new source literal — requires schema update
    trigger_type="community_idea",
    symbol="TAOUSDT",
    urgency="info",                      # default; agent upgrades if actionable
    message="[Author]: [Idea title] — [truncated description or full text]",
    raw_payload={
        "idea_url": "https://...",
        "author": "...",
        "published_at": "...",
        "likes": 142,
        "full_text": "..."               # populated if browser-assisted reading enabled
    },
    suggested_action=None               # agent determines from idea content
)
```

**Note:** Requires adding `"tradingview_idea"` to the `source` Literal in the TriggerEvent schema (TIS-001 schema update).

## Proposed Architecture

```
RSS Poller
(per-symbol, configurable interval)
        ↓
Idea Filter
(recency, author, likes threshold)
        ↓
[Optional] Browser Reader
(Claude in Chrome — full text extraction)
        ↓
Idea Normaliser
(→ TriggerEvent with source: "tradingview_idea")
        ↓
TIS Agent_Evaluation_Queue
(standard enrichment + agent evaluation path)
```
