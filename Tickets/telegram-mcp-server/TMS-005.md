# TMS-005: Refactor Telegram MCP into Service Client + MCP Wrapper

**Priority:** High

**Type:** Refactor

---

## Summary

Separate the Telegram MCP server into two layers: a standalone service client (`telegram_client.py`) that can be called from anywhere (Lambda, EC2, scripts), and a thin MCP wrapper (`mcp_server.py`) that exposes the client as MCP tools for agent use.

## Architecture

```
telegram_service/
├── client.py          # Core: send_message, send_alert, get_updates, edit_message
│                      # Pure Python + httpx. Takes bot_token + chat_id.
│                      # Callable from Lambda, EC2, scripts — no MCP dependency.
│
└── mcp_server.py     # MCP wrapper: exposes client.py as MCP tools
                       # For interactive agent use (Claude Code, Kiro, Bedrock)
```

## Why

- Lambda functions need to send Telegram messages without MCP protocol overhead
- The Telegram Bot API calls are simple HTTP — wrapping them in MCP for non-agent consumers adds unnecessary complexity
- Decoupling enables: Lambda direct calls, EC2 service calls, test scripts, future services
- The MCP wrapper stays for agent use cases (Claude Code, Bedrock tool use)

## Tasks

- [ ] Extract core Telegram Bot API calls into `telegram_service/client.py`
  - `async send_message(text, chat_id=None, reply_to_message_id=None) → message_id`
  - `async send_alert(text, chat_id=None) → message_id`
  - `async edit_message(message_id, text) → bool`
  - `async get_updates(offset=None, timeout=None) → list[dict]`
  - Constructor takes `bot_token` and default `chat_id`
  - Uses `httpx.AsyncClient` for HTTP calls
  - No MCP imports, no MCP protocol
- [ ] Refactor `mcp_server.py` to import and wrap `client.py`
  - Each MCP tool becomes a thin wrapper: parse args → call client method → return result
  - No business logic in the MCP layer
- [ ] Publish `client.py` as importable from the package (`from telegram_service import TelegramClient`)
- [ ] Verify all existing MCP tool tests still pass
- [ ] Add unit tests for `client.py` in isolation (mocked httpx)

## Acceptance Criteria

- [ ] `TelegramClient` importable and usable without MCP dependencies
- [ ] Lambda can call `TelegramClient.send_message()` directly
- [ ] Existing MCP tools work unchanged (backward compatible)
