# AEF-011: Permission Compliance Eval Dimension

## Summary

Add a new eval dimension that verifies the agent respects user permissions and org hierarchy boundaries — users should only see data within their org scope. This was flagged as critical for MVP by Bcurve stakeholders.

## Blocked By

The permissions enforcement mechanism must be designed and implemented first. Research is needed to determine where enforcement happens (data layer, API, MCP tools, agent prompt, or combination). This ticket cannot proceed until that research is complete.

## When to Pick Up

After the permissions enforcement mechanism is implemented and the team understands where boundaries are enforced.

## Scope

- New eval dimension: `permission_compliance`
- Test cases with multiple user personas (org admin, regular user, cross-org user)
- Ground truth specifying which vehicles/data each test user should and should not see
- Code grader: verify tool calls include correct user context (user_id, org_id)
- Model grader: verify response does not contain data outside user's org scope
- Note: If permissions are enforced at ORM/MCP layer (deterministic), code grader may suffice. If agent must self-restrict, model grader is critical.
